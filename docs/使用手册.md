# 恒见 GEO · 使用手册

> 版本：2026-10-27 ｜ 适用：本机 / 服务器部署 ｜ 命令：`node bin/geo.js <命令>`

---

## 0. 一句话说明

**这套系统做三件事：**
1. **看**：你的品牌在 13 个 AI 引擎里被不被提、怎么被说、引了谁；
2. **改**：告诉你改什么（内容、官网、信源、实体信息），并追踪改了有没有用；
3. **交**：把结果变成客户能看的报告、周报、分享链接和结算单。

## 1. 五分钟上手

### 1.1 启动

```bash
cd ~/Documents/deepseek-harness/default-workspace/hengye-geo

# 启动控制台（本机 8787 端口）
node server.js
```

打开 http://127.0.0.1:8787 ，用管理员账号登录：

- 用户名：`admin`
- 密码：首次启动时终端打印的初始密码（或启动时设 `ADMIN_PASSWORD=你的密码`）

> 对外部署时务必加两个环境变量：`BASIC_USER` / `BASIC_PASS`（运维兜底登录，也阻止陌生人打开登录页）。

### 1.2 看第一个客户

1. 左侧导航 → **总览**：最近一轮分数、运行历史、引擎密钥状态
2. 顶部 → **跑诊断**：选引擎（先用 `mock` 不花钱）、题数 → 点「开始」
3. 跑完 → **语义份额驾驶舱**：趋势、多引擎覆盖、竞品份额、引用源
4. **回答浏览器**：逐条看 AI 原话

### 1.3 没配 AI 密钥也能用

不配密钥时系统用 `mock` 引擎跑演示数据（报告顶部标 `[DEMO]`），**流程完整、不能对外**。
配一个 `DEEPSEEK_API_KEY` 就能跑真实采集（12 题约 ¥0.3）。

## 2. 三种角色

| 角色 | 登录后能看 | 能做什么 |
| --- | --- | --- |
| **管理员 admin** | 全部客户 | 建客户、建账号、开订阅、白标、计费、审计、全部功能 |
| **代理 agent** | 只有自己名下客户 | 建客户、给客户开订阅/续费、看客户看板与周报，进不了全局设置 |
| **客户 client** | 只有自己品牌 | 自助版：自己跑诊断；托管版：只读报告与周报 |

客户账号由管理员在 **客户管理** 页创建，创建时绑定品牌。

## 3. 客户全生命周期（最常用的流程）

### 3.1 新建客户

**页面**：`/clients` → 「新建客户」填品牌名、slug（英文短名）、城市、官网 → 创建
（创建后自动生成 36 道种子问题，开箱可跑诊断）

**命令行**：

```bash
node bin/geo.js init --brand 客户slug
```
（`init` 会读取 `brands/<slug>.json`；页面创建的客户只用数据库即可，不需要这个文件。）

### 3.2 开通订阅（自助 / 托管）

**页面**：`/clients` → 「开通 / 续费订阅」选客户、模式、套餐、天数 → 开通

| 模式 | 客户能做什么 | 建议定价 |
| --- | --- | --- |
| `self_service` 自助版 | 自己登录跑诊断、看驾驶舱、出周报 | ¥299–699/月 |
| `managed` 托管版 | 只读看报告与周报，动作由服务商完成 | ¥1,500–3,000/月（按效果计费见 §7） |

**命令行**：

```bash
node bin/geo.js client --slug 客户slug --mode managed --plan pro --days 30
node bin/geo.js client --list          # 查看所有客户订阅状态
```

套餐：基础版 ¥299（120 题/月、2 席位）· 专业版 ¥699（400 题、5 席位）· 服务商版 ¥1999（1500 题、20 席位）。

### 3.3 跑一轮诊断

**页面**：`/run-diagnose` → 选引擎与题数 → 开始（约 1–3 分钟）
**命令行**：

```bash
node bin/geo.js diagnose --brand 客户slug --engines deepseek --limit 12
```

引擎选项：`mock`（演示）· `live`（所有已配置）· 指定某家（`deepseek`、`claude`、`perplexity`…）

### 3.4 看结果

| 页面 | 回答什么问题 |
| --- | --- |
| `/` 总览 | 最近一轮多少分、跑了多少轮 |
| `/cockpit` 语义份额驾驶舱 | 提及率/份额/趋势/多引擎/竞品/引用源，一屏看全 |
| `/responses` 回答浏览器 | AI 原话是什么、判定是什么、引了哪条链接 |
| `/insights` 可见度分析 | 引用源、SoV、fan-out、证据等级 |
| `/alerts` 异动告警 | 这周掉了没有、涨了没有 |
| `/attribution` 内容归因 | 发的哪篇文章被引用了 |
| `/compare` 竞品对位 | 同一个问题 AI 推竞品还是推我 |

### 3.5 出周报 / 月报

```bash
node bin/geo.js weekly --brand 客户slug                 # 生成周报（MD + HTML）
node bin/geo.js weekly --brand 客户slug --push https://企微webhook地址
node bin/geo.js report --run 23 --pdf                    # 报告导出 PDF（需本机 Chrome）
```

页面：`/weekly` 直接看周报（自带样式，可打印）。

### 3.6 给客户看（分享链接）

```bash
node bin/geo.js share --run 23 --days 30 --base https://你的域名
node bin/geo.js share --list
node bin/geo.js share --revoke <token>
```

客户打开 `https://你的域名/s/<token>` 即可看只读报告，**无需登录**；到期自动失效，可随时吊销。

## 4. 合规：事实库与发布追踪（2026 新增，抗幻觉）

### 4.1 为什么有这一页

AI 把价格、资质、地址说错一次，客户会被投诉甚至处罚。所以内容只能引用**登记过、有来源、在有效期内**的事实。

### 4.2 登记事实

```bash
node bin/geo.js facts --brand 客户slug --add \
  --key legal_name --value "芜湖恒野数字科技有限公司" \
  --source "https://官网/about" --owner "负责人" --valid-days 365
```

关键事实 5 项：`legal_name`（全称）、`city`（城市）、`address`（地址）、`phone`（电话）、`price_range`（价格区间）。

查看健康度：`node bin/geo.js facts --brand 客户slug --health` 或页面 `/facts`。

**规则**：缺来源 / 过期 / 未核验的事实不可用于内容与报告。

### 4.3 发布追踪与撤回

```bash
# 登记发布时带上账号与引用的事实
node bin/geo.js publish --content 3 --channel 公众号 --url https://… --account 运营账号 --facts price_range,legal_name

# 发现错误 → 撤回并留原因
node bin/geo.js retract --publication 3 --reason "价格已变更"
```

系统会自动标风险：已发布但没 URL、没账号、没登记事实、引用了过期事实、发布超 90 天未复核。

## 5. 内容生产与分发

```bash
node bin/geo.js questions --brand 客户slug --count 36 --write     # 自动出题
node bin/geo.js brief --brand 客户slug --keyword "芜湖内容代运营"  # 生成 brief
node bin/geo.js write --brand 客户slug --content 6                # 写稿（四道闸 + 七维终审）
node bin/geo.js video --content 6 --style 口播科普 --duration 60  # 短视频脚本 + SRT + 分镜 CSV
node bin/geo.js distribute --all                                  # 11 渠道批量分发（默认 dry_run）
node bin/geo.js publish --list                                    # 渠道三态与配置方法
```

- **公众号真实发布**（唯一官方 API）：配 `WECHAT_APPID` / `WECHAT_SECRET` → `publish --channel 公众号`
- **知乎/头条/百家号/小红书/抖音**：浏览器半自动，见 §9
- **信源库**：`node bin/geo.js media --search 知乎 --count 2` 看渠道成本与发布方式

## 6. 监测与告警

```bash
node bin/geo.js monitor --brand 客户slug        # 快速监测（对比上次）
node bin/geo.js alerts --brand 客户slug         # 异动告警（可 --push 推送 webhook）
node bin/geo.js watch --brand 客户slug --configure --interval 60 --engines live --limit 12
node bin/geo.js watch --brand 客户slug --run    # 立即巡检一次
node bin/geo.js watch --brand 客户slug --status # 状态与历史
node bin/geo.js watch --brand 客户slug --install# 生成 cron 配置
```

告警阈值（设置页或直接改 settings）：`alert_mention_drop_pt`（默认 15）、`alert_score_drop`（10）、`alert_competitor_gain_pt`（20）。

> 系统本身不常驻：巡检靠 cron / launchd / systemd 触发，`--install` 会打印可直接粘贴的配置。

## 7. 托管按效果计费（结算）

```bash
# 出某月结算单（默认口径：新增 AI 提及条数 × ¥80）
node bin/geo.js bill --brand 客户slug --month 2026-10
node bin/geo.js bill --brand 客户slug --month 2026-10 --baseline-run 20   # 指定基线轮次
```

四种口径：新增提及条数 / 新增引用条数 / 提及率百分点 / 被推荐次数。
规则：效果为负按 0 计（不倒收费）、支持保底与封顶、每个数字可在看板核对。

页面：`/billing`（服务商与代理可见）。

## 10. 开放 API（客户系统对接）

```bash
# 创建密钥（明文只显示一次）
node bin/geo.js apikey --create --name 客户A --brand 客户slug --scopes read,share
node bin/geo.js apikey --list
node bin/geo.js apikey --revoke 1
```

调用（Bearer，作用域 read/share/write，限流 120 次/分钟）：

```bash
curl -H "Authorization: Bearer geo_xxx" https://你的域名/api/v1/state
curl -H "Authorization: Bearer geo_xxx" https://你的域名/api/v1/insights?run=23
curl -H "Authorization: Bearer geo_xxx" https://你的域名/api/v1/alerts
curl -X POST -H "Authorization: Bearer geo_xxx" -d '{"runId":23,"days":30}' https://你的域名/api/v1/share
```

接口：`/me` `/state` `/runs` `/insights` `/alerts` `/attribution` `/compare` `/share`。

## 13. 常见问题

**Q：诊断跑完没分数？**
A：有效样本不足。覆盖率低于 50% 不出总分（没测成 ≠ 0 分）。补题数或换可用引擎。

**Q：提到率很高但自有引用 0？**
A：AI 在讲你，但引的是别家。去 `/attribution` 看引了谁；补 llms.txt / JSON-LD / 问答页。

**Q：显示「未提及」但我确实被提了？**
A：可能命中同名实体（如「河南恒野农牧」）。检查品牌配置里的 `rejectedNames` 与 `disambiguation`。

**Q：客户说自己被 AI 推荐了，系统说没有？**
A：口径不同。系统只统计**本次采集的引擎与问题**；换引擎/换问题再跑，或看 `/responses` 的原话证据。

**Q：新客户不能跑诊断？**
A：检查订阅是否开通/到期（托管客户不能自己跑，是设计如此）。

**Q：数据在哪、怎么备份？**
A：全部在 `app/data/geo.db`（SQLite）。备份：`cp app/data/geo.db backup-日期.db`；报告在 `app/data/reports/`。

**Q：换域名？**
A：改 `GEO_PUBLIC_URL`；分享链接会按新域名生成，老链接仍可用（token 不变）。

## 16. 排障

| 现象 | 处理 |
| --- | --- |
| 打不开控制台 | `node server.js` 是否在跑；端口是否被占（会自动顺延到 8788…） |
| 登录 401 | 密码错 / 账号被停用；重设：删 `users` 表里该账号后用 `ADMIN_PASSWORD` 重启 |
| 采集全失败 | `doctor --probe` 看引擎；检查密钥、额度、网络 |
| 页面 403 | 角色不对：客户只能看白名单页面；托管客户不能执行动作 |
| 分享链接 404 | token 过期/被吊销/域名不符；重新 `share` |
| PDF 失败 | 本机没有 Chrome：设 `CHROME_PATH`，或浏览器打印成 PDF |
